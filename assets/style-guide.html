统一规范的核心只有一句

所有视觉取值都来自 :root 里的变量和一张刻度表，页面正文里不出现「随手写的颜色」和「随手写的字号」。变量收口 + 离散刻度，就是整体看起来协调的根本原因，不是审美玄学。

规则具体做法
强色占比墨绿只出现在章节编号、链接、目录当前项、状态词、步骤序号上，全页强色面积控制在 5% 以内；大面积一律用 soft 版或灰阶。
成对出现每个强色都配一个同色相的 soft 底色（--accent-soft 等），用于徽标 / 提示块背景，不要另调一个新颜色。
文字层级靠灰阶正文 / 次要 / 弱化三级灰阶分工明确，标题才用字重区分；不靠把文字加粗或改字号来制造层级。
唯一反相只有 pre 用深色底。其余区块（卡片、表格、提示）全是浅底 + 1px 边框，代码块因此天然成为视觉焦点。
氛围极轻body::before 用 7% / 6% 透明度的双色径向渐变做页首光晕，pointer-events:none，不参与内容层级。

04组件规范

九个组件覆盖长文所需的全部表达：章节、卡片、提示 / 引用、行内代码、代码块、表格、步骤、元信息胶囊、状态词。下面每个都是真实渲染。

4.1　章节头：编号 + 标题 + 一句导语

每章都用同一个三段式结构重复，秩序感就来自这种可预期。编号用等宽字 + 主色浅底，标题不用分割线。

<!-- 结构 -->
<section id="sec-01">
  <h2><span class="idx">01</span>章节名</h2>
  <p class="sec-lead">一句话说明本章解决什么</p>
  …
</section>

4.2　卡片 .card / .cards / .badge

三列并排用于「并列选项 / 三种阶段」，单列用于承载一段完整内容。徽标有三种配色，对应 A/B/C 或主次顺序。

4.3　引用与提示 .callout 四态

原稿没有用 <blockquote>：所有引用、笔记、警告统一走 .callout，好处是能带标题、带语义色，不必再维护第二套样式。四态各有「浅底 + 同色相边框 + 深色正文 + 主色标题」，色相和语义固定绑定。

4.4　行内代码 code

暖灰底 #f0eee7、棕字 #8a4a12、4px 圆角、字号取父级的 0.88em，white-space:nowrap 不换行。像 start_after_reboot.cmd 或 --port 9931 这类碎片用它；刻意与深色代码块区分开，读者一眼能分辨「一个词」和「一段命令」。

4.5　代码块 .codewrap > pre

全页唯一深色区块：#121a24 底、#dce6f0 字、12px 等宽、行高 1.75、10px 圆角、横向可滚动。语法只上三种色——注释灰蓝 .cmt、关键字薄荷 .key、字符串沙金 .str，不做完整语法高亮，避免花掉。右上角复制按钮由页面底部脚本自动注入。

# 一行写完，PowerShell 不认反斜杠续行
llama serve -m "model.gguf" -ngl 99 -c 8192 -np 1
写命令示例时的一条硬规则

Windows 命令给一整行可复制的文本，不要用 \ 分行续行——PowerShell 不认，复制过去会报错。长命令宁可横向滚动。

4.6　表格 table

规则很克制：无竖线、只有横向分隔线（--line2）、表头浅米底 #f5f3ed + 11.5px 次要灰、单元 10×12、最后一行去底线、hover 仅微变底色。数字列加 .num 用等宽右齐感，是/否用 .yes / .no 着色。

容易被忽略但很值钱的一条

教程类页面一定要写 @media print。深色代码块直接打印会糊成一片黑、耗墨且看不清；break-inside:avoid 能防止表格和代码块被拦腰截断。这套规则已经内置在 doc-style.css 里，「打印 → 另存为 PDF」直接就能用。

06为什么看着舒服

把上面的数值抽象成七条可迁移到任何页面的原则——换一套配色也照样成立。

  1. 颜色先做减法。一个主色 + 两个语义色，其余全是灰阶；强色面积 < 5%，只标「要你注意」的位置。多数页面显乱，是因为用了四个以上互不相干的色相。
  2. 层级靠灰阶，不靠加粗。四级文字灰阶把「正文 / 说明 / 注释 / 元数据」分开，读者不用比较字重就知道哪句重要。
  3. 取值离散化。字号 12 个固定值、间距 8 个值、圆角 6 个值，所有元素从表里挑，不出现 17px、19px 这种「差不多」的数。均匀节奏是秩序感的来源。
  4. 浅底 + 1px 描边统一所有区块。卡片、表格、提示块共用一种容器语言，只有代码块反相，形成唯一视觉焦点。
  5. 正文行高与行宽一起管。中文 1.85 行高、正文列不超过约 890px；光调字号不调行距，长文照样累眼。
  6. 结构重复。每章都是「编号 + 标题 + 一句导语」，表格都是「表头 + 无竖线」，读者扫一眼就知道当前在读什么。
  7. 交互做轻。hover 只变一个色阶、没有阴影堆叠、动画 0.15s。目录当前项用一条 2px 主色左边线就够了，不需要整块高亮。
一句话总结

先定义系统，再写页面。先把 :root、字阶表、间距刻度、组件清单定死，之后所有内容只是往格子里填；反过来边写边调样式，几乎必然出现「这里 13px、那里 17px、这块换个蓝」的漂移。

07复制给 AI 的生成指令

以后要生成同类 HTML，把下面这段连同内容一起发出来即可。也可以直接说「按 doc-style.css 的规范生成」。

【布局】1200px 容器，左 216px sticky 目录 + 52px 沟槽 + 正文列，目录随滚动高亮；
920px 断点目录横排、卡片单列；

标题禁止孤行，表格与代码块 break-inside:avoid。

【交付】目录锚点全部有效、标签闭合、无控制台报错；
代码块带复制按钮；内容按「一次性 / 每次 / 日常」分层，术语与文件名保持准确。
用指令时的两个小提醒

① 指令是约束，不是内容——记得把你自己的素材一起贴上，AI 才不会编造文件名和数值；② 如果后续要长期做同类页面，直接说「引用同目录的 doc-style.css」比把整段变量再贴一遍更省，也更容易保持一致。

08文件清单

三个文件放在同一目录，缺一个都不影响另外两个；只要 CSS 与 HTML 同级即可。

doc-style.css　—　通用样式表。从教程页内联样式逐条提取，数值一字未改，按用途补了分组注释。所有页面的视觉来源。

版式规范_可复用HTML样式.html　—　本页。规范说明 + 全部组件的真实渲染 + 可复制的生成指令。

模板_空白文档.html　—　最小骨架。已放好页首、目录、章节、表格、代码块、提示块占位，复制改名后替换文字即可。

教程_从升级llama.cpp到提示词工作流.html　—　原件，保持不动，作为效果对照。

改配色只需一步

打开 doc-style.css，把 --accent 和 --accent-soft 换成你自己的品牌色（一深一浅、同色相），引用它的所有页面会一起变。不要去改页面里的颜色——那正是规范要避免的漂移。
